# RIFFA Web — Obsidian Documentation

Структурированная документация проекта для Obsidian.

## 🚀 Как открыть в Obsidian

### 1. Установить Obsidian

Скачать с [obsidian.md](https://obsidian.md/)

### 2. Открыть папку как хранилище

1. Запустить Obsidian
2. "Open folder as vault"
3. Выбрать: `D:\Боты\RiffaBot\ВЭБ\Stable vers\riffaweb5\obsidian`

### 3. Начать с главной страницы

Открыть файл `00-INDEX.md` — это точка входа в документацию.

## 🔗 Особенности Obsidian

### Двусторонние ссылки

```markdown
[[01-Architecture|Архитектура]]
[[11-Generation#Lyrics Flow|Lyrics Flow]]
```

### Граф связей

`Ctrl+G` — открыть граф связей между заметками

### Теги

Все файлы имеют теги в frontmatter:
```yaml
---
tags: [architecture, structure, monorepo]
---
```

Поиск по тегам: `tag:#architecture`

### Метаданные (Frontmatter)

```yaml
---
type: documentation
category: feature
tags: [generation, suno, music]
related: [[12-Agent]], [[40-Quick-Start]]
---
```

### Быстрый поиск

- `Ctrl+O` — быстрый переход к файлу
- `Ctrl+Shift+F` — поиск по всем файлам
- `Ctrl+P` — командная палитра

## 📝 Как обновлять документацию

### Добавить новую заметку

1. Создать файл в нужной категории (10-19, 20-29, и т.д.)
2. Добавить frontmatter с метаданными
3. Добавить ссылку в `00-INDEX.md`
4. Связать с другими заметками через `[[ссылки]]`

### Обновить существующую

1. Открыть файл
2. Внести изменения
3. Обновить `last_updated` в frontmatter (если есть)
4. Проверить связи с другими заметками

### Пример frontmatter

```yaml
---
type: documentation
category: feature
tags: [tag1, tag2, tag3]
related: [[File1]], [[File2]]
last_updated: 2026-05-11
---
```

## 🎯 Workflow

### Для разработчика

1. Начать с `00-INDEX.md`
2. Изучить архитектуру: `01-Architecture.md`
3. Настроить окружение: `40-Quick-Start.md`
4. Выбрать задачу: `31-In-Progress.md`
5. Изучить модуль: `10-Authentication.md`, `11-Generation.md`, и т.д.

### Для планирования

1. Проверить `30-Completed.md` — что уже сделано
2. Посмотреть `31-In-Progress.md` — что в работе
3. Добавить в `32-Backlog.md` — новые идеи
4. Отметить в `33-Technical-Debt.md` — технический долг

### Для troubleshooting

1. Открыть `42-Troubleshooting.md`
2. Найти проблему
3. Следовать инструкциям
4. Если не помогло — проверить связанные файлы

## 🔄 Синхронизация с кодом

Документация должна обновляться вместе с кодом:

- ✅ Новая фича → обновить соответствующий файл
- ✅ Баг исправлен → переместить из `31-In-Progress.md` в `30-Completed.md`
- ✅ Новая проблема → добавить в `42-Troubleshooting.md`
- ✅ Технический долг → добавить в `33-Technical-Debt.md`

## 📊 Преимущества Obsidian для проекта

1. **Локальное хранение** — все файлы в git
2. **Markdown** — читается везде, не только в Obsidian
3. **Связи** — легко навигировать между темами
4. **Граф** — визуализация структуры проекта
5. **Поиск** — быстрый поиск по всей документации
6. **Теги** — группировка по категориям
7. **Версионность** — история изменений через git
