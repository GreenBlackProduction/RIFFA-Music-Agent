# AGENT-ANALYSIS.md — Part A findings (2026-06-05)

Результаты разбора ИИ-агента. Дополняет план `AGENT-PLAN.md`.

## Архитектура (как агент работает)
- **Endpoint:** `backend/app/api/v1/agent.py` (2114 строк). Три ручки:
  - `POST /agent/chat` (1623) — основной чат. **Stateless**: фронт каждый раз присылает всю историю; пустая история → захардкоженный опенер без GPT.
  - `POST /agent/chat/stream` (1840) — стрим-версия того же.
  - `POST /agent/classify` (2014) — отдельный классификатор (mood/genre/reference) для wizard-чипов.
- **Один GPT-вызов на турн.** `gpt-4o` ↔ `gpt-4o-mini` через `_pick_model()` (1231). Параметры: `temperature=0.55`, `max_tokens=1800`, `response_format=json_object`. Клиент — `AsyncOpenAI` через APIYI (`openai_base_url`).
- **Сообщения** (1661): `_SYS_AGENT` (системный промпт) + язык ответа + `_build_user_context` + `_build_user_stats` + окно последних 40 турнов.
- **Ответ** — JSON: `reply, done, music_params, research_notes, prompt(deprecated), intent`. Парсится `_postprocess_agent_reply` (1718) с salvage при битом JSON.
- **НЕТ tools / function-calling.** Агент не может ничего «вызвать» — только сгенерировать текст.
- **История чата НЕ персистится** в БД. В `generations.params` сохраняется только финальный бриф (`agent_music_params`, `agent_research_notes`, `agent_prompt`).

## Корень бага «не ищет исполнителя, берёт не того, застревает» — ПОДТВЕРЖДЁН
- `track_reference.resolve_reference(raw, lastfm_api_key)` **умеет** заземлять и ссылку, и **plain-имя** («Burial», «Daft Punk - …») → Deezer-поиск → `{artist,title,bpm,year,era,genre,tempo,tags}` (+ Last.fm-теги, если есть ключ).
- **НО вызывается только в `/classify` (строка 2082), НЕ в `/chat`.** В живой беседе референс не заземляется → `gpt-4o` опирается на свои знания → на нишевом/региональном/неоднозначном артисте **домысливает** (берёт не того).
- `_SYS_AGENT` содержит «FAST PATH» (215): после упоминания артиста НЕ задавать вопросы, сразу строить бриф → агент **коммитит ошибочного артиста** и застревает. «CONFABULATION GUARD» (380) рассчитан на честность модели, но без реального поиска не спасает.
- **`lastfm_api_key` пуст** (`config.py:76` default `""`, в `ops/.env` нет) → даже `/classify` сейчас грунтит только Deezer, без богатых тегов.
- Подтверждение по БД: брифы owner'а — это LLM-описания («Lorn's style…», «Shibuya Kodia… lo-fi»), т.е. без поискового заземления.

## Скорость / стоимость
- **`_SYS_AGENT` = 51 142 симв ≈ 12 800 токенов, 977 строк — на КАЖДЫЙ турн.** Это доминирующий фактор латентности и цены (input-токены) на gpt-4o. Плюс окно 40 турнов.
- Роутинг gpt-4o↔mini уже есть (экономит на болтовне), но shaping-турны всегда тяжёлый 4o с гигантским промптом.
- *Осталось:* замерить реальную латентность турна live (нужен залогиненный токен).

## Рекомендации (приоритет)
1. **Заземлять референс в `/chat`** (главное): при детекте артиста/референса в сообщении вызывать `resolve_reference` (Deezer + Last.fm) и класть факты (genre/era/bpm/tags/похожие) в контекст/`research_notes` — модель опирается на данные, а не догадки. Нет хита → честно сказать и переспросить.
2. **Function-calling:** дать модели tool `search_reference(query)`, чтобы она сама вызывала поиск, когда не уверена (чище, чем «знаю/не знаю» в промте).
3. **Ужесточить FAST PATH / CONFABULATION GUARD:** при низкой уверенности И отсутствии хита — `done=false` + уточняющий вопрос/варианты, а не коммит.
4. **Включить Last.fm** — задать `LASTFM_API_KEY` в `ops/.env` (owner проверяет ключ).
5. **Урезать `_SYS_AGENT`** (977 строк → компактные секции, вынести примеры) — заметный выигрыш по скорости и цене.
6. **UX смены референса** во фронте (`AgentChat.tsx`) — явная команда, чтобы не «уговаривать».
7. **Наблюдаемость:** логировать на турн модель, латентность, был ли поиск, уверенность, финальные params.
